# 확정 제품 정책

2026-10-27 사용자 정의를 기준으로 한다. 과거 인계 문서에서 미정으로 남은 재신청 정책은 이 문서를 따른다.

| 구분 | 정책 |
| --- | --- |
| 결과 페이지 | 곡마다 하나의 고정 주소. 재신청·다운로드 후에도 같은 주소에서 상태를 다시 읽는다. |
| 다운로드 권한 | 저장 완료부터 최대 7일, 차수마다 1회. 서버 전송 시작 시 사용 완료로 확정하고 실제 음원을 삭제한다. |
| 재신청 자격 | 최초 음악 생성 시각부터 50일 미만. 생성 시각은 재신청으로 바꾸지 않는다. |
| 재신청 횟수 | 제한 없음. 같은 곡의 동시 재신청은 차단한다. |
| 유효한 다운로드가 있을 때 재신청 | 기존 권한을 즉시 종료하고 기존 음원을 먼저 삭제한 뒤 같은 음악을 조회·검증·저장한다. |
| 재신청 후 다운로드 | 새 저장 완료부터 다시 최대 7일·1회. 50일 직전 재신청도 새 7일을 유지하므로 최종 다운로드는 생성 후 약 57일까지 가능하다. |
| 완료 안내 | 메일 또는 카톡으로 동일한 결과 페이지 주소를 다시 안내한다. 페이지를 새로 만들거나 바꾸지 않는다. |

결과 페이지의 인증과 다운로드 차수의 권한을 분리한다. 이전 차수의 다운로드 요청은 새 차수의 사용권을 소진할 수 없다. 결과 페이지에서는 듣기·다운로드·재신청·진행/실패/만료 상태를 확인한다. 새로고침해도 같은 페이지를 사용한다.

삭제 대상은 Supabase Storage의 실제 오디오다. 같은 음악의 검증·복구를 위해 곡 ID·최초 생성 시각·파일 해시·크기·MIME·처리 이력은 DB에 남긴다. 브라우저가 이미 받은 오디오 바이트를 회수하거나 저장 완료를 신뢰성 있게 감지하는 기능은 아니다.

기존 Google Interaction이 없거나 원본 해시와 다르면 복구 실패로 처리한다. 새로운 음악 생성·자동 재생성으로 대신하지 않는다. 50일은 재신청 자격 기간이며, Google의 결과 보관을 검증 없이 보장하는 표현은 사용하지 않는다.

현재 구현은 고정 페이지·재신청·기존 음원 교체·원본 검증·다운로드·삭제까지다. 메일·카톡 전송과 수신처 설정은 아직 연동 전이다. 완료 알림은 `pending_setup` 대기 기록으로만 남기며 실제 전송 완료로 표시하지 않는다.
