# 고객 API 연결 준비 및 배포 확인

## 준비 결과

기존 Supabase 프로젝트에 `nosayeon-result-api` Edge Function을 추가하는 코드를 준비했다. 기존 고객 권한 검증·원본 해시 검증·1회 다운로드·삭제 처리를 재사용한다. 브라우저는 기존 고정 링크의 fragment에서 토큰을 읽고 Authorization 헤더로 API에 전달한다. 토큰을 query에 넣거나 새 사이트 소스에 저장하지 않는다.

- 제안 API: `https://fuvgpqkyhuyanbfavwcg.supabase.co/functions/v1/nosayeon-result-api`
- 연결할 사이트: `https://nosayeon-result-check.cw-lee.chatgpt.site` (기존 소유자 비공개 접근 유지)
- Supabase 서비스 역할 키는 Supabase가 제공하는 함수 런타임 환경에서만 사용한다. 클라우드 Secret을 읽어 출력하거나 Sites로 복사하지 않는다.
- 고객 결과·오디오·다운로드 API만 허용한다. 관리자·메일·새 음악 생성은 없다.
- `verify_jwt=false`는 기존 고객 전용 43자 capability 토큰을 함수 본문에서 검증하기 위한 설정이다. 데이터 API를 무인증으로 열지 않는다. 유효한 토큰과 일치하는 곡만 허용한다.
- CORS는 기존 임시 사이트 원점 하나만 허용한다. CORS 자체를 인증으로 취급하지 않는다.
- 새 함수의 Google 복구 런타임은 아직 연결하지 않아 재신청 버튼과 처리를 비활성으로 둔다. 기존 로컬 복구 기능은 유지한다.
- `/healthz`는 DB 연결 여부만 반환하며 행·건수·키·고객 정보를 반환하지 않는다.

## 실제 배포 상태

**배포하지 않았다.** 자동 승인 검토가 함수 공개 배포를 거절했다. 거절 사유는 서비스 역할 권한으로 비공개 오디오·DB에 접근하는 인터넷 접근 가능 서비스 경계를 만드는 행위가 기존 페이지 연결 요청에 포함됐는지 불명확하다는 것이었다. 이를 다른 CLI나 간접 배포로 우회하지 않았다.

기존 Sites는 정적 화면 검증 버전을 유지한다. 새 실연결 페이지 후보는 `artifacts/hosted-result-site/`에만 준비했으며 배포하지 않았다. 기존 Supabase 함수·음원·고객 토큰·다운로드 상태를 바꾸지 않았다. 실제 추가 메일·음악 생성도 없다.

## 검증

- 자동 테스트 127개 통과.
- 새 hosted adapter의 Origin/CORS/preflight, 경로 제한, 고객 토큰 필수, 서버 전용 정보 미노출을 검증했다.
- 로컬 모의 데이터로 재생은 다운로드 횟수를 사용하지 않고 다운로드만 한 번 소비·삭제 예약을 하는지 검증했다.
- 별도 브라우저에서 실연결 페이지 후보가 지정 Edge API만 호출하고 Authorization 헤더에 합성 토큰을 전달하는지 검증했다. 모의 오디오 재생·모의 다운로드 완료·미설정 재신청 숨김을 확인했다.
- 실제 API·원본 MP3를 호출한 성공 검증은 아직 하지 않았다. 기존 비공개 결과 링크 자료는 여전히 이 작업 공간에 없다.

## 사용자에게 확인할 선택지

1. 인증된 고객 API의 임시 배포 승인: 위에 명시한 경계와 기능으로 Supabase 함수를 배포하고 기존 비공개 사이트에 연결한다. 배포 후 비밀값 없는 상태 검사와 잘못된 토큰 차단부터 확인한다. 실제 원본 다운로드·재신청·추가 메일은 별도다.
2. 배포 보류: 현재 비공개 화면 검증 사이트를 유지하고 준비한 코드는 저장한다.

승인 후에도 원래 곡 토큰을 자동 교체하지 않는다. 기존 링크 보관 자료를 확보하는 단계는 별도다. `scripts/package-result-edge.mjs`가 배포할 정확한 소스 파일 목록을 구성하고, `scripts/prepare-hosted-result-site.mjs`가 사이트용 실제 페이지 후보를 생성한다. Sites 배포는 기존 Site ID를 재사용한다.
