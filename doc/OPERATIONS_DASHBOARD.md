## 인증·데이터 경계

고객 공용 비밀번호로 관리자에 들어가지 못한다. Sites의 소유자 접근 정책과 플랫폼 로그인을 사용하며 API에도 플랫폼 식별자 또는 별도 서버 서비스 호출을 요구한다. 서버 전용 `ADMIN_INGRESS_KEY`는 Sites Secret으로만 설정한다. DB에는 SHA-256 해시만 저장한다. 원문 키는 브라우저·소스·문서에 넣지 않는다.

기존 앱 설정 파일 `artifacts/request-service/runtime.json`에 별도 adminKey를 0600으로 보관한다(Git 제외). 기존 key/ingressToken/sessionKey는 바꾸지 않았다. 공급자 키나 DB 서비스 역할 키를 Site에 복사하지 않았다. 관리자 Site가 공개로 바뀌면 현재 보호 전제가 달라지므로 항상 owner-private을 유지한다.

DB operations_access/song_worker_events는 RLS 서비스 전용, 새 RPC는 SECURITY INVOKER이며 anon/authenticated 실행을 차단했다. 고객용 접수 키로 관리자 API를 호출하면 실제 401이다. 목록 수신처는 일부 마스킹하고 상세에서만 주소/사연을 조회한다. 결과 토큰·암호문·서버 키·Storage 경로는 반환하지 않는다.

대시보드 조회는 클라우드 음악 작업자를 거치지 않고 Site→Edge→DB로 실행하므로 작업자 중단 상태도 볼 수 있다. DB/API 자체가 응답하지 않을 때는 연결 오류와 이전 조회 시각을 표시하고 숫자를 0으로 대체하지 않는다. 자동 갱신은 현재 열린 화면에서 20초마다 GET만 수행한다.

## 진단·한계

반복 중단의 확인된 증거와 재현 명령은 [WORKER_OUTAGE_DIAGNOSIS.md](WORKER_OUTAGE_DIAGNOSIS.md)를 따른다. 새로운 작업자는 시작 단계와 안전한 오류 코드/타입을 출력하고 DB에 기록 가능한 경우 이벤트를 보관한다. 신청 실패도 phase/error_code를 보충한다. DB까지 연결되지 않는 실패는 이벤트 저장도 실패할 수 있어 로컬 로그를 함께 봐야 한다. 이전에 없던 과거 진단 이벤트를 추측해 채우지 않는다.

상시 호스팅, 관리자 운영 조치, 다중 관리자 권한/조치 감사, 자동 알림은 아직 후속 과제다. 오늘 지표는 한국 날짜, 신청 한도는 최근 24시간 전체로 구분한다. 용량은 DB/파일 사용량이며 요금제 한도나 청구 사용량을 추정하지 않는다.
