```sh
npm ci       # 전체 테스트를 위한 개발 의존성 설치
npm run dev  # 내부 테스트 페이지: http://127.0.0.1:4173
npm test     # 외부 API 호출 없는 테스트
```

Node.js 24.5 이상, 페이지 실행에는 Python 3가 필요합니다. 프롬프트 준비 화면은 음악을 생성하지 않습니다. 실제 테스트 음악 1곡은 이미 생성·재조회해 파일 해시 일치를 확인했습니다. 추가 생성 대신 저장된 실행 폴더에 `--resume`을 사용하세요.

Supabase 실제 프로젝트에 DB 마이그레이션과 비공개 버킷 구성을 적용하고, 기존 MP3의 업로드·재다운로드 SHA-256 일치를 확인했습니다. `npm run storage:import -- --run <기존 실행 폴더>`는 외부 호출 없이 원본 파일을 검사합니다. 장기 보관 기간 전체의 실증과 카카오 전송은 아직 미완료입니다. Gmail 직접 첨부 테스트는 실제 수신까지 확인했습니다.

`npm run dev` 실행 후 `/result-preview.html`에서 예시 데이터 기반 상태별 화면을 확인할 수 있습니다. 실제 `/result.html`은 `npm run result:serve`에서 같은 주소로 듣기·1회 다운로드·50일 이내 무제한 재신청을 제공합니다. 재신청하면 이전 파일을 먼저 삭제하고 같은 음악을 복구해 새 7일 보관 기간을 시작합니다. 15분 간격 자동 정리도 운영 중입니다. Gmail 완료 안내와 고객 전용 서버 코드는 구현했습니다. 공개 호스팅과 완료 안내 발송 활성화는 아직 진행하지 않았습니다. 카카오는 후속 작업입니다.

### 고객 결과 페이지 디자인

결과 화면은 아이보리 배경과 음반 일러스트, 전용 재생·일시정지 버튼, 재생 위치 탐색과 음소거, 다운로드 버튼으로 구성합니다. 모바일 화면에서도 사용할 수 있습니다. `/result-preview.html`에서 준비 완료·다운로드 완료·만료·준비 중·재신청 실패·보관 종료·잘못된 링크·오류의 8가지 화면을 실제 데이터 없이 확인할 수 있습니다. 미리보기의 재생·다운로드·재신청은 비활성화되어 있습니다.

실제 결과 페이지는 기존 인증·음원 검증 API와 연결합니다. 재생만으로 다운로드 횟수를 사용하지 않고, 다운로드 전송 시작 시 사용 완료되는 정책을 유지합니다. 재신청 후에도 페이지 주소는 동일합니다. 고정 결과 페이지 버튼을 담는 완료 안내 메일은 구현했고, 공개 호스팅 연결·수신처 및 Secret 등록·발송 활성화는 후속 설정입니다.

### 결과 페이지 완료 안내와 배포 준비

`npm run notification:preview`로 실제 발송 없이 최초·재신청 완료 메일을 확인합니다. `notification:configure`는 기존 비공개 결과 링크의 수신처와 암호화 토큰을 등록하며, `notification:deliver`는 명시적 실행 옵션과 활성 설정이 모두 있을 때만 신규 대기 건을 처리합니다. 곡·차수마다 한 번 점유하고 `failed`·`sending`·`unknown`은 자동 재발송하지 않습니다. [완료 안내 운영](doc/RESULT_EMAIL_OPERATIONS.md)을 참고하세요.

`npm run result:public`과 `Dockerfile`은 관리자 기능을 제외한 고객 결과 서버용입니다. 현재는 외부 배포 전이며 HTTPS 프록시·공개 원점·서버 Secret 설정이 필요합니다. [배포 준비](doc/RESULT_DEPLOYMENT.md), [다음 작업 인계](doc/NEXT_SESSION_HANDOFF.md)에 현재 상태를 기록합니다.
